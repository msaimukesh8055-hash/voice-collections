### Goal

Srinivas can **talk** to the bot: a WhatsApp voice note in Telugu, Hindi, English or a mix becomes the same Save card as a typed message, and the bot can answer with a voice note. For the demo, each Telugu message also shows its English underneath, and **Sarvam Translate** gives English versions of what was heard and said in Telugu/Hindi. "insights" sends a **pie chart**, % collected and the **top 5 defaulters**, and the **web dashboard** shows the whole book. After M6 the pitch uses all of Sarvam's stack: Indus (Asha), `sarvam-105b`, **Saaras**, **Bulbul** and **Translate**.

### Acceptance criteria (SPEC §17 M6 = demo steps 1 and 7; §6.6, §6.7, §12)

- **Voice in:** a voice note goes through Saaras speech-to-text, then the same command → LLM path as text. The card shows "🎤 Heard: …". Nothing is saved without Save
- **Voice out:** when Srinivas sent a voice note, the reply also comes as a short voice note (Bulbul). Figures are always in the text too
- **Translate:** the "Heard" line and call transcripts get an English version from Sarvam Translate. Names and amounts are never changed (tested)
- **English under Telugu:** a setting. When on, every Telugu text message is followed by a blank line and its English version
- **Spacing:** bot messages have blank lines between title, sections and footer
- **Insights:** pie chart image (collected / not yet due / overdue, this month), % collected, total outstanding, change vs last week, top 5 defaulters with amount, days overdue and score, and a dashboard link
- **Dashboard:** `/` KPIs, pie, top 5, recent calls (demo controls kept); `/shopkeepers` with score parts, notes, promises; `/calls` with transcript, tool calls, tone level, summary, live/simulated, cost. Light-blue theme. (`/evals` is M7)
- **Small:** "overdue" and "who is overdue" open the due alert; the lookup shows the last call note
- **Done when:** the smoke test below passes on Saim's phone and Chrome

### Facts checked (Sarvam docs, 2026-11-04)

| Question | Answer | What it means for us |
|---|---|---|
| Does Saaras take WhatsApp's audio (OGG/Opus)? | Yes: WAV, MP3, AAC, OGG, **OPUS**, FLAC, M4A, AMR, WebM… are accepted directly | **No conversion needed.** We pass Meta's file straight to Saaras |
| Saaras limits | REST call is for audio **under 30 s**; returns `transcript` and the detected `language_code`. Models `saaras:v3` (modes: transcribe, translit, **codemix**…) and `saaras:v4` (default; `keyterms`, up to 50 words it should listen for) | Voice notes over 30 s get "please keep it under 30 seconds". The detected language picks the reply language |
| Bulbul output | WAV (default), MP3, AAC, FLAC. **Opus returns an error on v3 / v4-flash.** Max 2,500 characters. `bulbul:v4-flash` has `kavitha_te_conversation` (Asha's voice is Kavitha) | WhatsApp shows a green "voice note" bubble only for OGG/Opus. MP3 plays fine but looks like an audio file (Decision 3) |
| Translate | `mayura:v1`: 1,000 characters, modes formal / modern-colloquial / **code-mixed**. No "keep these words" option | We protect names and amounts ourselves (Decision 4) |
| Prices (pay as you go) | Saaras **₹0.49/min**; Bulbul v3 **₹3 / 1,000 chars**, v4-flash **₹2 / 1,000 chars**; Translate **₹2 / 1,000 chars**; `sarvam-105b` ₹15 / ₹60 per 1M tokens | See cost table below |

*Opus = the sound format WhatsApp uses for voice notes. Codemix = English words stay in English letters, Telugu/Hindi words in their own script.*

### How a voice note works (new in M6)

```
Voice note ──► Meta ──► whatsapp-webhook (signature, owner, once — as in M4)
   message type "audio" → media id
   ① GET graph.facebook.com/{media id} → download link → download the .ogg (Meta token, max 1 MB)
   ② length from the file itself (> 30 s → "please keep it under 30 seconds")
   ③ Saaras speech-to-text → transcript + language (te / hi / en)
   ④ same brain as text: fixed command → sarvam-105b → Gemini
   ⑤ reply text (in the detected language, + English under Telugu if on), card shows "🎤 Heard: …"
   ⑥ voice reply: short spoken version → Bulbul → upload to Meta → send as audio
Audio and transcript are never stored; wa_messages keeps type "voice", seconds, language and path.
```

### Decisions

#### Decision 1: Build in two halves, each with its own check
📊 **Options:** (a) **6a voice + language**, then **6b insights + dashboard**, each tested and checked before the next · (b) one build.
✅ **My recommendation:** (a). If time runs out, 6b is cut using the SPEC order (dashboard detail first), and voice notes (the demo opener) are already safe.

#### Decision 2: Which Saaras model and mode
🔍 The bot's code parser reads English letters ("Ramesh 5000 due 15th"). Telugu or Hindi script goes to the LLM.
📊 **Options:** (a) **`saaras:v3`, mode `codemix`**: "Ramesh కి 5,000 credit, 15th వరకు". Reads naturally on the "Heard" line; Telugu/Hindi parts go to `sarvam-105b` (≈₹0.02 extra) · (b) `saaras:v3`, mode `translit` (all in English letters: "Ramesh ki 5,000 credit, 15th varaku"): the code parser catches more, but the "Heard" line looks odd to a Telugu reader · (c) `saaras:v4` with `keyterms` = up to 50 shopkeeper names: better at names, newer model.
✅ **My recommendation:** (a), decided by a **10-minute spike** (piece 6a-1): you record 3 voice notes (Telugu-English, Hindi-English, English) and run them through (a), (b) and (c) on your laptop. Cost ≈ ₹1. We keep whichever gets names and amounts right. Misheard names are already handled: the M4 pick list and the card (R9).

#### Decision 3: Voice reply format
📊 **Options:** (a) **Bulbul → MP3 → WhatsApp audio message**. Plays inside WhatsApp with a play button, but shows as an audio file, not a green voice-note bubble · (b) convert to OGG/Opus inside our function with an audio encoder (WebAssembly) for a real voice-note bubble. Heavier, may not run in Supabase's Edge runtime, +30–40 min · (c) try `bulbul:v2`, which may still accept Opus (older voices, no Kavitha).
✅ **My recommendation:** (a) now; (b) only if you want the bubble look for the recording, as a later 40-minute piece.
📐 **What it says:** a **spoken version**, not the whole message: formatting removed, amounts read as "5,000 rupees", and only the title plus the first 3 rows of a list (e.g. "12 people owe you 1,84,000 rupees. Top is Ramesh, 8,500."). Cards are spoken in full ("…Tap Save to keep it."). Voice: `bulbul:v4-flash`, **Kavitha** in Telugu and Hindi (same voice as Asha), English: closest female conversational voice. ⚠️ **Voice choice is yours**; I'll send you 3 samples in the spike.
📐 Only replies to a voice note get a voice reply. If Bulbul fails, the text still goes out (voice is best effort).

#### Decision 4: Sarvam Translate — live, only for text we can't write in advance (changed by Saim, 2026-11-04)
🔍 The Hindi and Telugu versions of every fixed bot line already exist (hand drafts from M4/M5). Re-translating them all would cost build time (a script, plus slots in every line) and mostly give us a second draft of what we have.
✅ **Agreed:** fixed lines stay **hand-drafted** (native-speaker check still open). Sarvam Translate is used **live** where the text is unknown until the moment:
1. **"🎤 Heard:" line** — a Telugu or Hindi voice note's transcript gets its English underneath, when the "English under Telugu" setting is on (Telugu and Hindi notes; English notes need nothing).
2. **Call transcripts on the dashboard** — each Telugu/Hindi line of a call gets an English version next to it, translated once and saved on the call, so the pitch audience can follow.
📐 `mayura:v1`, source language from Saaras (or the call's language), mode `code-mixed` (Saim may switch to `modern-colloquial` after seeing samples). **Names and amounts:** masked before translation (`⟦1⟧`, `⟦2⟧`…) and put back after; a reply that loses a mask is thrown away and the original shown alone (tested). Translate failing never blocks a reply.
💰 A "Heard" line ≈ 60 characters ≈ ₹0.12; a 3-minute call transcript ≈ 1,500 characters ≈ ₹3, once per call (only when the dashboard opens it).

#### Decision 5: "English under Telugu" demo setting
📐 A new setting on the owner: `owners.english_under_telugu` (yes/no), **on** for Srinivas in the seed (Saim), off by default for any new owner, with a switch on the dashboard's demo controls.
📐 When on: every Telugu **text** gets a blank line and the same message in English. **Changed during the build (Saim, 2026-11-04):** the English is made by **Sarvam Translate** live (names and amounts protected), because building every message twice from our own tables would have meant changing every message builder (~1.5–2 h). ≈₹0.5–1 per Telugu message, only while the setting is on. Buttons and list rows stay Telugu only (WhatsApp allows 20–24 characters there). Voice notes stay Telugu only. If the doubled message is too long for WhatsApp (1,024 characters on messages with buttons), the English goes in a second message right after.
📊 **Also for Hindi?** Saim asked for Telugu. ✅ **My recommendation:** Telugu only, as asked; Hindi is one line of config if you want it.

#### Decision 7: Insights — what the numbers mean (money, 100% tested)
📐 All on the **demo-clock** date, worked out in code from the ledger (oldest credit paid first, as in `dues.ts`):

| Figure | Meaning |
|---|---|
| **Pie: collected / not yet due / overdue** | Credits **due this month**: the part already paid, the part still owed and not yet due, the part owed and past its due date |
| **% collected** | Collected ÷ all credit due this month |
| **Total outstanding** | All unpaid balances, any month |
| **Change vs last week** | % collected today vs the same figure 7 days ago ("▲ 6 points") |
| **Top 5 defaulters** | Biggest overdue amount first (ties: more days overdue), with days overdue and score band |

📊 **Alternative:** pie of the whole book (all outstanding) instead of this month. ✅ **My recommendation:** this month, as SPEC §6.6 says; total outstanding covers the whole book.

#### Decision 8: Drawing the pie chart (SPEC D3: inside our function)
📊 **Options:** (a) **draw an SVG and turn it into a PNG with `resvg` (WebAssembly) plus one bundled font**: labelled slices and a title, English labels and digits in the image (a Telugu font is too big for the function); the caption carries the figures in Srinivas's language · (b) paint the PNG pixel by pixel in our own code: no library, but no text in the image (colours only, legend in the caption) · (c) an outside chart service: breaks D3 (data leaves our stack).
✅ **My recommendation:** (a), checked in a 15-minute spike at the start of piece 6b-2; if `resvg` won't load in Supabase's Edge runtime, fall back to (b). The PNG is uploaded to Meta's media API and sent as an image; nothing is stored. The same chart colours (collected green, not yet due blue, overdue red-orange) are used on the dashboard.

#### Decision 9: Dashboard access and pages
🔍 The browser only has the public Supabase key, and every table is closed to it (RLS, no policies). SPEC §12: "opened from the WhatsApp link, which carries a short-lived token".
📊 **Options:** (a) **signed link**: "insights", "pending" (when there are more than 10) and the new "dashboard" command send a link with a token signed by our function (`DASHBOARD_LINK_SECRET`, 24 hours). The page sends it to new read-only `calls-api` routes; no token or an old one → "Open the dashboard from WhatsApp: send *dashboard*" · (b) open dashboard with no check (fake data only, but anyone with the address sees it).
✅ **My recommendation:** (a). The token sits after `#` in the link so it isn't written to server logs; the page keeps it for the browser tab only.
📐 **Pages:** `/` (KPIs, pie, top 5, last 10 calls, then the demo controls) · `/shopkeepers` (search, list with balance and score band; one shopkeeper: score with its 4 parts, ledger, promises, notes) · `/calls` (list with live/simulated label; one call: transcript, tool calls, tone level, summary, cost). Charts drawn as plain SVG in React, no chart library; the tiny path switch in `App.tsx` stays (no router library for 4 pages).
📐 **Cost per call** on `/calls`: live = minutes rounded up × ₹3.50 + GST; simulated = LLM tokens × price, shown as "≈".
⚠️ Until the Vercel deploy (M8), the link points to `DASHBOARD_URL` (your laptop's `http://localhost:5173`), so it opens from WhatsApp Web on the laptop.

#### Decision 10: Spend guards for voice
📐 Voice notes over 30 s or 1 MB are refused before Saaras is called. A daily cap of **50 voice notes and 50 voice replies** (counted in `wa_messages`); past the cap, text only, with a one-line notice. Same idea as the 20-live-calls-a-day cap from CP2.
✅ **My recommendation:** as above.
